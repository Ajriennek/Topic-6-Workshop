# Review checklist
- Establish purpose, contract, scope and source/destination branches.
- Inspect all changed files and necessary caller/context code.
- Check correctness, invalid inputs and inclusive/exclusive boundaries.
- Evaluate names, flow, duplication and fit with existing code.
- Inspect test inputs and assertions; identify missing cases and weakened tests.
- Check documentation, errors and stated preconditions.
- Compare manual findings with configured lint and actual test results.
- Identify relevant risk or specialist expertise needed; stay within scope.
- Distinguish required corrections, questions, suggestions and preferences.
- Recheck revisions against every applicable requirement.
- Record the reviewed commit, decision, limitations and individual contributions.

Comment pattern: location; observation; consequence; requested action; verification.
A question can block approval if its answer is necessary to judge correctness.
